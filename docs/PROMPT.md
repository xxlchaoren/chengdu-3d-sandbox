# 生成提示词 · Prompt Spec

本项目由一段**经过外部调研打磨过的提示词**驱动生成。下面既是它的成品，也是可复用的规格说明——直接把它交给编码代理，应当能重建出同等品质的城市沙盘。

原始需求只有一句：

> 3D 城市沙盘，城市是成都市。

先去网上看别人怎么做 3D 城市沙盘（见 [REFERENCES.md](REFERENCES.md)），发现两件事：一是绝大多数 demo 的通病是**"任何城市都长这样"**——随机方块＋霓虹发光边线＋网格地面，换个城市名毫无差别；二是**可辨识度和性能天然对立**，靠堆模型解决不了，只能靠"把城市结构写进生成规则"。于是把提示词重写成下面的验收标准。

---

## 一、任务

用 Vite + TypeScript + Three.js 生成一个**成都市 3D 城市沙盘**，纯前端、可离线运行、无构建产物以外的资源依赖。

## 二、硬性约束（违反即返工）

1. **可辨识性优先**：截图遮住 UI 后，一个成都人必须能认出这是成都。做不到就重来，不要用文字标注补救。
2. **零外部请求**：不加载模型、贴图、字体、CDN、瓦片、 GeoJSON。整城几何 100% 由代码生成。要有自动化测试守住这条。
3. **规模**：数千到数万栋建筑，通过 `InstancedMesh` 压到 1000 次 draw call 以内；中端 GPU 60 fps。
4. **性能预算**：首帧 < 5 s（实测约 1.3–1.5 s）；页面不出现 > 2 s 的空白等待。
5. **真实尺度**：定义明确的单位换算并在文档写明；地标高度、环半径、 River 方位必须来自可核实的数据，不许凭印象编。
6. **确定性**：可复现随机种子，同一刷新同一座城市（便于截图、测试与回归对比）。
7. **质量门禁**：`tsc --noEmit` 无错、`npm test` 全绿、`npm run build` 通过。

## 三、让"成都"成立的具体要求

抽象的"像"没有指导意义，必须拆成可判定的几何条件：

- **路网拓扑**：成都的骨架是**环＋放射**（8 条环线 + 17 条放射干道），不是方格网。建筑必须沿极坐标格网采样，密度随环带变化。这是与北京（正南正北棋盘）、上海（沿黄浦弯折方格）最根本的区别，也是第一优先级。
- **地形边界**：西面龙门山抬升约 4400 m、北面约 3000 m、东面龙泉山约 850 m，成都平原被三面山地把控。晴夜西方天际线要出现**雪山轮廓**——"窗含西岭千秋雪"是成都的空间特征，2025 年中心城区遥望雪山 81 天。
- **绿环**：半径 12.1–14.9 km 处必须是一条**连续的低密度绿带**（环城生态公园／天府绿道绕城段，一级绿道 100 km、串 121 个生态公园），把"公园城市"读出来。
- **水系走向**：府南河、摸底河、沙河等 10 条河流呈**西北—东南**向穿城，11 处湖泊（青龙湖、锦城湖、升仙湖…）按实际方位落位。水系不能是装饰性蓝线。
- **地标**：手工建模至少包括天府双塔（含连桥幕墙）、绿地中心 468、蜀峰 460、西博城、环球中心、成都东站、大魔方、339 天府熊猫塔、宽窄巷子、武侯祠、杜甫草堂、金沙、交子金融环，并带建成年份。
- **时区修正**：成都太阳时比东经 120° 基准**晚约 1.062 h**，日落常在北京时间 20:00 前后。光照模型必须内置该修正，否则黄昏出现在错误的位置，整个夜景调子都会跑偏。

## 四、渲染与观感

- 昼夜循环必须**分时刻可调**（清晨/正午/黄昏/深夜预设），夜间是主展示态：窗光按随机比例点亮、街道走廊自发光、轨道线发光、地形铺开光污染薄毯。
- 夜景的光要**分层**：屋顶近黑、沿街墙脚受路灯洒亮。整片均匀发黄＝失败；只描边发亮＝失败（会变成"华夫饼"）。
- Bloom 只作用于自发光；ACES Filmic 色调映射。白天压住半球光，避免城市被洗成薄荷色纸板；盆地雾霾应当是**灰白带暖**，不是青绿。
- 材质差异化：玻璃幕墙（低 roughness）与混凝土／塔式住宅（高 roughness）分开，否则正午屋顶会 specular 过曝成一团白。

## 五、交互（沙盘必须是"可查的"）

图层独立显隐（地形/绿地/水系/路网/车流/建筑/地标/轨道/标注）、视角预设切换、地标列表点击**平滑飞入**、点击拾取弹信息卡、时间/天气/品质可调、状态持久化。

飞入是高频 bug 点：注意**距离单位在投影函数与相机模块之间是否一致**。

## 六、迭代协议（关键）

一次性生成不可能达到可辨识度。要求**按截图判定、按轮次收敛**：

1. 每轮改完，导出 4 个基准视角（沙盘/全景/地标飞入/地图）在固定时刻的截图。
2. 读像素摘要（核心区域 RGB 均值）判断整体明暗与色偏，再肉眼看结构是否成立。
3. 每轮只改一个变量并记录，避免多处同时改动导致无法归因。
4. 后台标签页 rAF 不跑、原生截图不可用时，用 `gl.readPixels` + `OffscreenCanvas.convertToBlob` 同源回传的离线出图管线替代。

## 七、验收（全部通过才算完成）

- [ ] 遮住 UI 的截图能被成都人认出城市
- [ ] 数千至数万栋建筑，draw call < 1000，60 fps
- [ ] 昼夜/天气/图层/飞入/拾取全部工作，经 DOM 级冒烟测试
- [ ] 零外部网络请求（有自动化测试）
- [ ] 首帧 < 5 s
- [ ] `tsc --noEmit` 干净、测试全绿、构建通过
- [ ] 中文 README + 数据来源与近似说明文档

## 八、明确不要做的事

- 不要赛博朋克霓虹描边大屏风（那是"任意城市 + 特效"，不是成都）。
- 不要引入 `@react-three/fiber`、Cesium、Mapbox、DEP/倾斜摄影等依赖来换便利——本沙盘的约束就是纯 Three.js + 程序化。
- 不要用文字标签代替可辨识度。
- 不要垂直夸张地形来"做出雪山"；用真实幅度（1:1）。
